[ 1 ] 가공 데이터 수집 시나리오
--------------------------------------------------------------------------------

현재는 가공이 끝난 뒤 폴더에서 수동으로 가져오는 방식이다.
단계적으로 자동화 수준을 올릴 수 있다.


1-1. 현재 단계 - 사후 수동 수집

    가공 종료
      -> 장비가 폴더에 파일 세트 출력
      -> 사람이 경로 지정
      -> python -m orcus.etl.load_real_data 실행


1-2. 다음 단계 - 폴더 감시 자동 적재  (가장 현실적)

    watchdog 으로 수집 폴더 감시
      -> 파일 생성 감지
      -> 쓰기 완료 대기 (크기 안정화 확인)
      -> work_id 폴더 단위로 묶임 판정
      -> 기존 적재 파이프라인 호출
      -> 결과를 적재 이력 테이블에 기록

    [주의] 파일 쓰기가 끝나기 전에 읽으면 깨진 데이터가 들어간다.
           크기가 N초간 변하지 않을 때 완료로 판정하는 처리가 필수.
           TDMS 는 700MB 이상이라 복사에 수십 초가 걸릴 수 있다.


1-3. 장기 단계 - 장비 실시간 연동

    방식            대상               특징
    ------------    ---------------    --------------------------------------
    FANUC FOCAS     DNM200 제어기      부하/좌표/알람 실시간. 라이선스 필요
    MTConnect       제조 표준          XML 스트림, 어댑터 필요
    OPC-UA          범용               설비 지원 여부 확인 필요


1-4. 수집 시점별 데이터 매핑

    시점       데이터                        적재 테이블
    -------    ---------------------------   ---------------------------------
    가공 전    XML, NC, 공구 셋업            tb_job, tb_tool_usage
    가공 중    ext.log (10Hz)                tb_machine_load
               TDMS (12.8kHz, 6채널)         tb_daq_waveform
    가공 후    치수, 표면조도                tb_quality_inspection
               공구 마모량                   tb_tool_inspection
               환경 관찰                     tb_job_environment

[ 2 ] 이상치 탐지 - 현재 데이터의 제약
--------------------------------------------------------------------------------

모듈을 만들기 전에 반드시 인지해야 할 제약 사항이다.

    (1) 지금 바로 쓸 수 있는 지표는 spindle_load 하나다.
        cutting_force_rms (afrms) 는 _coeff.xml 의 절삭력 계수가
        미설정이어서 전 구간 0 이다. 사용 불가.

    (2) job 이 5 건뿐이라 job 간 통계 비교는 표본이 부족하다.
        따라서 job 내부 구간 비교 방식으로 접근한다.

    (3) DAQ 원시 파형은 보존되어 있으므로, 청크별 RMS 를 뽑으면
        12.8kHz 기반 분석도 가능하다. 2 단계 확장 대상.

    -----------    ----------------------------------    --------------------

[ 4 ] 탐지 방법
--------------------------------------------------------------------------------

4-1. 전처리 (필수)

    is_cutting = 1 인 구간만 사용
        -> 비절삭 구간의 0 값이 통계를 왜곡한다

    tool_code_active 로 구간 분리
        -> 공구마다 정상 부하 범위가 다르다


4-2. 기준선 방식

    IQR (사분위수 범위)
        분포 가정 없음, 이상치에 강함. 첫 적용으로 적합
        하한 = Q1 - k*IQR,  상한 = Q3 + k*IQR  (k 기본 1.5)

    이동중앙값 +- k*MAD
        시계열용. 추세를 따라가며 급변만 잡아낸다
        MAD = 중앙값절대편차 (Median Absolute Deviation)

    Isolation Forest
        부하/RPM/이송/좌표를 함께 보는 다변량 기법
        데이터가 더 쌓인 뒤 적용 권장


4-3. IQR 을 3시그마보다 먼저 쓰는 이유

    3시그마는 평균과 표준편차를 사용하는데, 이상치 자체가
    그 값을 끌어올려 탐지를 무디게 만든다.
    IQR 은 중앙값 기반이라 이상치의 영향을 받지 않는다.

[ 5 ] Claude Code 프롬프트 - 1단계 : 데이터 상태 진단
--------------------------------------------------------------------------------

아래 내용을 Claude Code 에 그대로 붙여넣는다.

--------------------------------- 복사 시작 ---------------------------------

이상치 탐지 모듈을 만들기 전에 현재 데이터 상태를 진단해줘.
추측하지 말고 실제 DB를 쿼리해서 결과만 보여줘.

1. job별 부하 데이터 분포:
SELECT job_id, COUNT(*) AS n,
       SUM(is_cutting=1) AS cutting_rows,
       ROUND(AVG(spindle_load),2) AS avg_load,
       ROUND(MIN(spindle_load),2) AS min_load,
       ROUND(MAX(spindle_load),2) AS max_load,
       ROUND(STDDEV(spindle_load),2) AS std_load
FROM tb_machine_load GROUP BY job_id;

2. 절삭 구간만 본 분포:
SELECT job_id, tool_code_active, COUNT(*) AS n,
       ROUND(AVG(spindle_load),2) AS avg_load,
       ROUND(MAX(spindle_load),2) AS max_load
FROM tb_machine_load
WHERE is_cutting=1
GROUP BY job_id, tool_code_active
ORDER BY job_id, tool_code_active;

3. 사용 가능한 센서 컬럼 판별 - 전부 0이거나 NULL인 컬럼을 찾아줘:
spindle_load, spindle_current, spindle_speed_rpm, feed_override,
pos_x, pos_y, pos_z, cutting_force_rms 각각에 대해
COUNT(*), COUNT(컬럼), SUM(컬럼 != 0), MIN, MAX 를 구해줘.

4. extra_json 안에 실제 값이 변하는 필드가 있는지 확인해줘.
   job 하나를 골라 샘플 100행의 extra_json 을 파싱해서,
   값이 항상 0인 필드와 변하는 필드를 구분해서 목록으로 보여줘.

5. DAQ 청크 구조 확인:
SELECT job_id, channel_name, COUNT(*) AS chunks,
       MAX(samples_in_chunk) AS samples_per_chunk,
       MAX(sampling_rate_hz) AS hz
FROM tb_daq_waveform GROUP BY job_id, channel_name;

결과를 표로 정리하고, 이상치 탐지에 쓸 수 있는 컬럼과
쓸 수 없는 컬럼을 판단해서 알려줘.

--------------------------------- 복사 끝 -----------------------------------

[확인 포인트]
    4번 결과가 특히 중요하다. extra_json 안에 값이 변하는 필드가
    더 있으면 탐지 대상 지표가 늘어난다.

[ 6 ] Claude Code 프롬프트 - 2단계 : 탐지 모듈 구현
--------------------------------------------------------------------------------

1단계 진단 결과를 확인한 뒤 진행한다.

--------------------------------- 복사 시작 ---------------------------------

이상치 탐지 모듈을 orcus/analysis/ 에 만들어줘.

[전제]
- 탐지 대상은 tb_machine_load 의 spindle_load (10Hz 시계열)
- cutting_force_rms 는 계수 미설정으로 전 구간 0이라 제외
- job이 5건뿐이라 job 간 비교 대신 job 내부 구간 비교로 간다

[파일 구성]
orcus/analysis/__init__.py
orcus/analysis/outlier.py     순수 함수 (DB 의존 없음)
orcus/analysis/detect_load.py CLI 진입점

[outlier.py 에 넣을 순수 함수]
- iqr_bounds(series, k=1.5) -> (lower, upper)
- mad_bounds(series, k=3.0) -> (lower, upper)   중앙값절대편차 기반
- rolling_outliers(series, window, k) -> bool 배열
    이동중앙값 대비 MAD 로 급변 탐지
- trend_slope(series) -> float   선형회귀 기울기 (마모 진행 지표)
- rolling_std(series, window) -> Series   채터 탐지용

[detect_load.py 처리 흐름]
1. job_id 를 인자로 받음 (없으면 전체)
2. tb_machine_load 에서 is_cutting=1 행만 조회
3. tool_code_active 로 구간을 나눔
4. 구간마다:
   - IQR 로 전역 이상치 판정
   - rolling_outliers 로 급변 지점 판정
   - rolling_std 급증 구간을 채터 후보로 표시
   - trend_slope 로 마모 추세 계산
5. 결과를 tb_load_anomaly 테이블에 INSERT

[신규 테이블 DDL - db/006_load_anomaly.sql 로 작성]
CREATE TABLE tb_load_anomaly (
    anomaly_id   BIGINT AUTO_INCREMENT PRIMARY KEY,
    job_id       INT NOT NULL,
    tool_code    INT              COMMENT '구간의 tool_code_active',
    detected_at  DATETIME(3)      COMMENT '이상 발생 시각(logged_at)',
    metric       VARCHAR(30)      COMMENT 'spindle_load 등 대상 지표',
    value        DOUBLE           COMMENT '해당 시점 실제 값',
    baseline     DOUBLE           COMMENT '기준값(구간 중앙값)',
    deviation    DOUBLE           COMMENT '기준 대비 편차',
    method       VARCHAR(20)      COMMENT 'IQR / MAD / ROLLING / TREND',
    severity     VARCHAR(10)      COMMENT 'LOW / MID / HIGH',
    note         VARCHAR(255),
    created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_anomaly_job FOREIGN KEY (job_id)
        REFERENCES tb_job(job_id) ON DELETE CASCADE,
    INDEX idx_anomaly_job (job_id, detected_at)
) ENGINE=InnoDB COMMENT='부하 시계열 이상치 탐지 결과';

[중요]
- 임계값(k, window)은 코드에 박지 말고 함수 인자 + CLI 옵션으로
- 재실행 시 중복 적재되지 않게, 같은 job_id 결과는 지우고 다시 넣을지
  물어보는 확인 절차 넣어줘
- 탐지 결과가 0건이어도 정상 종료하고 "이상치 없음" 출력

[주의] Windows 인코딩: 출력, 주석에 특수문자 쓰지 말고 ASCII, UTF-8

[ 7 ] Claude Code 프롬프트 - 3단계 : 대시보드 연동
--------------------------------------------------------------------------------

2단계가 끝난 뒤 진행한다.

--------------------------------- 복사 시작 ---------------------------------

app.py 에 "이상치 분석" 화면을 추가해줘.

- job 선택 + 지표 선택
- 부하 시계열 그래프 위에 탐지된 이상치를 점으로 표시

- 임계값 k 를 슬라이더로 조정하면 즉시 재탐지되게

기존 디자인 유지: 화이트 배경, 슬레이트 네이비(#22303C),
파스텔 블루(#5B9BD5), 코드값은 모노스페이스

[주의] Windows 인코딩: 출력, 주석에 특수문자 쓰지 말고 ASCII, UTF-8
